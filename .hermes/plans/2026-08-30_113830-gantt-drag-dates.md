# 甘特圖色塊拖曳改日期 — 可行性評估與實作計畫

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 在甘特圖右側 SVG 區直接拖曳專案色塊（移動＝整段平移）或拖曳色塊左右邊緣（縮放＝改起始/結束日期），放開即寫入新日期，免去開修改視窗。

**Architecture:** 純 Pointer Events（pointerdown/move/up + setPointerCapture）掛在既有 SVG `<rect>` 上，拖曳期間只渲染一個「幽靈色塊」（local state），放開才呼叫 `projectStore.update()` / `projectStore.updateMilestone()` 一次。擷取座標 → 日：`dayIdx = floor((clientX − svgRect.left + scrollLeft) / DAY_WIDTH)`，全部以既有常數 `DAY_WIDTH=24` 對齊日期欄，天然日粒度 snap。

**Tech Stack:** React 19 + TypeScript + SVG（無新依賴）。不用 frappe-gantt（它在 package.json 裡但本專案是自己刻的 SVG，勿引入其 drag 實作）。

## 可行性結論（先答問題）

**可行，中等複雜度，影響範圍可控。** 估計 GanttPage.tsx +~180 行、localStorageStore.ts 0–10 行，不動型別、不動同步機制、不動佈局。理由：

1. **資料層已就緒** — `projectStore.update(id, {start_date,end_date})`（localStorageStore.ts:365）與 `updateMilestone(id, {...})`（:575）都是現成的，emit `kanban:data-change` 自動刷新左右兩欄；拖曳結束只呼叫一次，不會造成 GitHub 同步壓力。
2. **座標系統簡單** — 固定 `DAY_WIDTH=24px`、日期欄在 `dateHeaders` 陣列裡，pixel↔date 換算是單行算術，天然以「天」為單位吸附，不需小數日。
3. **SVG rect 加 pointer handler 是標準做法** — React 對 SVG 的 pointer events 支援完整，`setPointerCapture` 讓滑鼠拖出視窗也不丟事件。

**風險與不便（誠實列出）：**

| 風險 | 嚴重度 | 緩解 |
|------|--------|------|
| 拖曳 vs 既有点擊（色塊 click→專案詳細、列 click→詳細、菱形 click→展開）衝突 | 中 | 移動 >4px 視為拖曳，拖曳結束時 suppress 該次 click（既有一顆 onMouseUp 标记即可）；菱形**不做拖曳**維持展開語意 |
| 手機觸控：垂直捲動、容器橫向捲動 vs 拖曳手勢搶事件 | 中 | 色塊上 `touch-action: none`（只有色塊本身，列背景不設）→ 手指碰到色塊才進入拖曳模式，其餘照常捲動。**建議第一版只做滑鼠（pointerType==='mouse'），觸控當第二階段**（見 Task 5） |
| 誤拖改到日期（沒有 undo） | 中 | 拖曳中顯示幽靈色塊+日期 tooltip 預覽；放開才寫入；配合置頂「今天」紅線讓誤拖可辨識。不做 undo（YAGNI，備份在 GitHub data repo） |
| 拖到视图邊界外（虛擬捲動） | 低 | 第一版 clamp 到 `viewStart..viewEndStr` 範圍內；auto-scroll 拖出邊界不做（YAGNI，30 天可視範圍通常夠用） |
| 父專案日期與子專案不一致（拖父不拖子） | 低 | 本專案父專案日期是獨立柱狀值（表單獨立輸入，無 rollup 機制）→ 拖父就只改父，**维持现况**，不發 rollup（避免動 store 語意）。跟用戶說明即可 |
| 單日色塊 24px 很窄，edge 只有左右各一圈 | 低 | edge 感應區向外擴 4px（透明 `<rect>` 疊在色塊兩端），cursor 顯示 ew-resize |

**對整體程式的影響評估：** 小。改动集中在 `GanttPage.tsx`（renderBar 加兩顆邊緣 rect + 一顆幽靈層 + 一個 hook），store 加一顆批次 `updateDates`（可選），型別、同步、其他頁面零改動。左側凍結欄完全不用碰（日期不可見於左欄）。

## Current context / 現況盤點（已于 2026-08-30 讀碼確認）

- 色塊渲染：`renderBar()` `GanttPage.tsx:596` — `<rect>` + `onClick={() => handleProjectClick(project.id)}`（:626）、`cursor: pointer`（:627）
- 專案列全寬背景 rect 也掛 onClick → 詳細（:1028）；菱形 diamond onClick → toggleExpand（:1049–:1053，已 `e.stopPropagation()`）
- 活動列色塊：milestone row `<rect>` onClick → `openEditActivity(m)`（:999–:1000）
- 捲動容器：`<div className="absolute left-[96px] top-0 right-0 overflow-x-auto">`（:920）→ 換算要加 `scrollLeft`
- 常數：`DAY_WIDTH = 24`（:10）、`HEADER_HEIGHT = 28`、`MILESTONE_ROW_HEIGHT = 32`
- 寫入 API：`projectStore.update(id, updates)` :365、`updateMilestone(id, updates)` :575、`projectStore.add()` 皆己 emit 事件；`useProjects().update` 已暴露
- 色塊幾何：`x = offsetDays*24`、`width = barDays*24`（含末日 +1 規則 :602，**拖放後回寫日期時必須用同一把尺**：`date = viewStart + round(x/24)`、`end = viewStart + round((x+w)/24) − 1 天`）
- 無測試框架 — 驗證 = `npm run build`（tsc）＋瀏覽器手動清單（本專案慣例）

## Proposed approach

新增一個頁面內 `dragState`（`{ kind:'move'|'resize-l'|'resize-r', target:'project'|'milestone', id, origX, origW, origStart, origEnd, newX, newW, moved:boolean }`）＋三個事件處理器（onPointerDown 開 / onPointerMove 更新幽靈 / onPointerUp 提交）。洩露 `updateDates` 走既有 store 方法。菱形不参与（無日期範圍語意衝突＋已負展開職責）。開關建议：不需開關，直接啟用（操作發現不直覺再退回也只是一段程式）。

拖曳算式（全部四捨五入到整天格）：

```
dayIdxPointer = (clientX − svgRect.left + svgScroll.scrollLeft) / DAY_WIDTH   // 可含小數
deltaDays(拖曳中) = Math.round(dayIdxPointer − grabbedDayIdx0)

move:      newX = origX + deltaDays*DAY_WIDTH   (clamp: 0 ≤ newX, newX+origW ≤ totalWidth)
resize-l:  newX = clamp(origX + deltaDays*DAY_WIDTH, 0, origX+origW-DAY_WIDTH)
resize-r:  newW = clamp(origW + deltaDays*DAY_WIDTH, DAY_WIDTH, totalWidth - origX)

提交（pointerup）：
startNew = addDays(viewStart, Math.round(newX / DAY_WIDTH))
endNew   = addDays(viewStart, Math.round((newX + newW) / DAY_WIDTH) - 1)   // 含末日規則
```

import { dateToStr } from '@/utils/dateUtils'  // 已 import；若缺 addDays 就近用 ms 算

const addDays = (dateStr: string, n: number): string =>
  dateToStr(new Date(localDate(dateStr).getTime() + n * 86400000))

/** pointer clientX → fractional day index within the SVG scroll space */
function pxToDay(clientX: number, svgRect: DOMRect, scrollLeft: number): number {
  return (clientX - svgRect.left + scrollLeft) / DAY_WIDTH
}

### Task 2: 專案色塊 — 拖曳移動（move）

**Objective:** renderBar 色塊可整段左右拖，幽靈預覽，放開寫入。

**Files:** Modify: `src/pages/GanttPage.tsx:596-642`（renderBar）+ 元件 handlers

**Step 1 — pointerdown handler（元件內）：**

```ts
const startDrag = useCallback((e: React.PointerEvent, opts: { kind: DragKind; target: 'project' | 'milestone'; id: string; x: number; w: number }) => {
  if (e.button !== 0) return
  e.stopPropagation()
  ;(e.target as Element).setPointerCapture(e.pointerId)
  const grabbedDay = svgRef && scrollRef.current
    ? pxToDay(e.clientX, svgRef.current.getBoundingClientRect(), scrollRef.current.scrollLeft)
    : 0
  setDrag({ kind: opts.kind, target: opts.target, id: opts.id,
    origX: opts.x, origW: opts.w, newX: opts.x, newW: opts.w,
    grabbedDay, moved: false })
}, [])
```

**Step 2 — onPointerMove（掛在 `<svg>` 上，:922）：**

```ts
const onSvgPointerMove = useCallback((e: React.PointerEvent<SVGSVGElement>) => {
  setDrag(prev => {
    if (!prev || !svgRef.current || !scrollRef.current) return prev
    const day = pxToDay(e.clientX, svgRef.current.getBoundingClientRect(), scrollRef.current.scrollLeft)
    const delta = Math.round(day - prev.grabbedDay) * DAY_WIDTH
    if (!prev.moved && Math.abs(delta) < 4 && Math.abs(e.movementX) < 2) return prev  // 4px threshold
    let { newX, newW } = prev
    if (prev.kind === 'move') newX = Math.min(Math.max(0, prev.origX + delta), totalWidthRef.current - prev.origW)
    else if (prev.kind === 'resize-l') { newX = Math.min(Math.max(0, prev.origX + delta), prev.origX + prev.origW - DAY_WIDTH); newW = prev.origW + (prev.origX - newX) }
    else newW = Math.min(Math.max(DAY_WIDTH, prev.origW + delta), totalWidthRef.current - prev.origX)
    return { ...prev, newX, newW, moved: true }
  })
}, [])
```

（`totalWidthRef` = 既有 `totalWidth` 的 ref 鏡像：`const totalWidthRef = useRef(totalWidth); totalWidthRef.current = totalWidth`。）

**Step 3 — onPointerUp（提交，掛 `<svg>`）：**

```ts
const onSvgPointerUp = useCallback((e: React.PointerEvent<SVGSVGElement>) => {
  setDrag(prev => {
    if (!prev) return null
    if (prev.moved) {
      const s = addDays(viewStart, Math.round(prev.newX / DAY_WIDTH))
      const en = addDays(viewStart, Math.round((prev.newX + prev.newW) / DAY_WIDTH) - 1)
      if (prev.target === 'project') update(prev.id, { start_date: s, end_date: en })
      else projectStore.updateMilestone(prev.id, { start_date: s, end_date: en })
    }
    suppressClickRef.current = prev.moved   // 拖過→吞掉後續 click
    return null
  })
}, [viewStart, update])
```

（`update` 從 `useProjects()` 取（已暴露）；`suppressClickRef = useRef(false)`。`handleProjectClick` 頭兩行：`if (suppressClickRef.current) { suppressClickRef.current = false; return }`。）

**Step 4 — renderBar 接上：**

```tsx

style={{ pointerEvents: 'auto', cursor: drag ? 'grabbing' : 'grab', touchAction: 'none' }}
```

**Step 5 — 幽靈色塊 + tooltip（`<svg>` 內最後，覆蓋層）：**

## 風險／開放問題

1. **滾動中拖曳（先拖再捲）不支援** — pointer capture 期間滚輪事件仍到容器，可能造成幽靈跟手错位；實作時在 pointerdown 鎖 `scrollRef.current.style.overflowX='hidden'`、up 還原（2 行，已计入 Task 2）。
2. **窄色塊（24px 單日）上 move 與 resize 感應區重疊** — edge 條 8px 宽已蓋住一半色塊；實則單日拖 move 抓手只剩中間 8px，可接受；若嫌難用，單日色塊預設 resize-r（拖任意處＝拉長）——開放問題，預留待回饋。
3. **無 undo** — 誤拖靠幽靈預覽防呆；如回饋需要，再加「Ctrl+Z 還原上一次拖曳」復原緩衝（單笔即可，~20 行）。
4. **活動列多活動重疊同區間** — 本視圖每活動一顆 rect 同 y 叠放，拖上層即可；不加欄位換行機制（YAGNI）。
5. 觸控体验未經驗證（此裝置無觸控屏可測）— 依 5 開關预案退回鼠標限定。

# Plan: 选题库（Topics Queue）— 每日一文的主题轮流工具

## Goal

为看板新增第五种物件「选题（Topic）」：储备一批文章主题进池，每天自动轮到下一个，一键「领题 → 完稿」，让"今天写哪篇"零记忆负担。

## Current context / assumptions

- Repo: `~/kanban/`（React 19 + TS + Vite 8 + Tailwind v4, HashRouter），已部署 GitHub Pages；资料经 `projectStore`（`src/data/localStorageStore.ts`）双写 LocalStorage + `PosenChen/kanban-data` 仓（GitHub Contents API，3 秒去抖自动上传，空覆盖防护 + sha 冲突侦测**已内建**）。
- 现有物件：Project / Milestone（活动）/ Todo / Routine（流水帐）/ LedgerEntry（记帐）/ Memo（备忘录）。新增 Ledger 与 Memo 时已固化一套标准作业模式（types → utils 纯函数 TDD → store CRUD+sync → page → 工具列入口 → README），本计划照抄该模式。
- 用户需求解读：主题池是**先进先出（FIFO）轮流队列**——储备不定时点、每天消费一篇；今日未交卷则明日顺延仍举同一题（writing 状态黏住）。
- 现有工具评估（为何需要新工具）：Memo 只能存+搜无队列语义；Todo 无日期轮换且完删失脉络；活动列日程做不了"池"。故新建。
- 本地测试模式：vitest node env，store 测试需 `installShim()`（见 `src/data/store.ledger.test.ts`）。
- 提交规范：每步 build→test→commit→push（Actions 自动部署）。

## Architecture / proposed approach

新增 `Topic` 型别 + `topicUtils.ts` 纯函数（取题/完稿/月度统计）+ store `kanban_topics` 同步（第六个 GitHub 档案 `data/topics.json`，须塞进 `writeGitHub`/`fetchRemoteCounts` 两处档案清单）+ `/topics` 页（今日题大卡 + 池 + 历史）+ 甘特图工具列 📚 入口。队列规则单点定义在 topicUtils，页面只消费。

### T3. topicUtils 实作（4 min）

创建 `src/utils/topicUtils.ts`：

```ts
import type { Topic } from '@/types/project'

/** 今日题：writing 黏住顺延；否则 sort_order 最小的 pool；池空 null */
export function todayTopic(pool: Topic[]): Topic | null {
  const w = pool.find(t => t.status === 'writing')
  if (w) return w
  return pool.filter(t => t.status === 'pool').sort((a, b) => a.sort_order - b.sort_order)[0] ?? null
}

/** 交卷：status done + done_date */
export function completeTopic(t: Topic, date: string): Topic {
  return { ...t, status: 'done', done_date: date, updated_at: new Date().toISOString() }
}

/** 领题：pool → writing */
export function claimTopic(t: Topic): Topic {
  return { ...t, status: 'writing', updated_at: new Date().toISOString() }
}

export function monthlyDoneCount(pool: Topic[], ym: string): number {
  return pool.filter(t => t.status === 'done' && t.done_date?.startsWith(ym)).length
}

/** 删除池内一题后，其余 pool 重排连续 sort_order */
export function reorderPoolAfterRemove(pool: Topic[], removedId: string): Topic[] {
  return pool.filter(t => t.id !== removedId && t.status === 'pool')
    .sort((a, b) => a.sort_order - b.sort_order)
    .map((t, i) => ({ ...t, sort_order: i }))
}
```

## Risks / tradeoffs / open questions

- **多装置同时领题**：sha 冲突防护会拒第二次覆盖并提示先下载——可接受（单人多装置低碰撞率）；不引入 CRDT（YAGNI）。
- **归档系统未纳 Topic**：done 题永久留池档案区；若日后嫌长再接 `archived_at`（入口已在 autoArchive 隔壁，预留成本低）。
- **文章正文放哪**：outline 仅作大纲/灵感；正文外链（如 Obsidian）——避免巨型 blob 进 JSON。开放问题：若用户要正文入库，再加 `body` 栏位即可（向后兼容）。
- 新档案 `topics.json` 首传前远端 404 属正常（readGitHubFileFull ok=false → guard 视为未知不误跳_pass 逻辑正常）_；已由现有 guard 覆盖。
